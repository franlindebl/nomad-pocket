# Nomad Pocket — guide for Claude sessions

Nomad Pocket is an offline-first iOS + Android app (Expo / React Native) that brings
[Project N.O.M.A.D.](https://github.com/Crosstalk-Solutions/project-nomad) to phones:
download knowledge (Kiwix ZIM archives: Wikipedia, medicine, survival, DIY, books,
courses), offline maps and a local AI model while online, then use it all with no
connection. GPL-3.0-or-later, public repo `github.com/franlindebl/nomad-pocket`, bundle id
`com.fjlinde.nomadpocket`, submitted to the App Store (ASC app 6826502392).

The owner writes in Spanish: answer in Spanish. Code, comments, commits and docs are in
English. User-facing strings are Spanish + English (i18n).

## Stack (exact versions matter)

- **Expo SDK 58**, React Native 0.88 (New Architecture, Hermes), React 19.3, React
  Compiler on, typed routes on. TypeScript 6, strict.
- **Expo has breaking changes every SDK: don't trust memory.** Before touching an Expo/RN
  API, read `https://docs.expo.dev/versions/v58.0.0/` (or `https://docs.expo.dev/llms.txt`).
- Expo Router (`src/app/`), native tabs (`expo-router/native-tabs`), native stacks and
  form sheets. State: zustand. Persistence: expo-sqlite (+ `expo-sqlite/kv-store`).
  Files: expo-file-system 58 (`File`, `Directory`, `DownloadTask`). i18n: i18next.
- Native: local Expo modules `modules/nomad-zim` (libkiwix/libzim),
  `modules/nomad-llm` (Apple Foundation Models, iOS only; Android offers downloadable models only) and `modules/nomad-route`
  (Valhalla routing via Rallista valhalla-mobile 0.6.4), `modules/nomad-files` (streaming sha-256
  and file copies for multi-GB downloads); `llama.rn` 0.13.0-rc.8
  (GGUF); `@maplibre/maplibre-react-native` 11.5 (+ `@protomaps/basemaps` styles).
- Min OS: iOS 16.4 (Expo 58 floor), Android 8.0 (API 26). CNG: `ios/` and `android/`
  are generated by `npx expo prebuild` and gitignored — **never edit them by hand**;
  configure in `app.json` / config plugins / `modules/*`.
- Package manager: **npm** (`package-lock.json`). Add deps with `npx expo install <pkg>`.

## Commands

```bash
npm install                 # postinstall fetches the libkiwix + Valhalla xcframeworks (iOS)
npx expo run:ios            # dev build on a simulator (or: npx expo run:android)
npm start                   # Metro for an installed dev client
npm test                    # unit tests: node --test with type stripping (~1 s)
npx tsc --noEmit            # typecheck
npx expo lint               # ESLint (eslint-config-expo)
npm run check:i18n          # every t('…') key exists in es and en
npm run check:catalog       # validates src/data/catalog.json + every URL (--offline: schema only)
node scripts/licenses.mjs   # regenerates src/data/licenses.json (Credits screen); --check fails if stale.
                            # Run after any dependency change; native libraries live in scripts/licenses/native.json
npm run e2e                 # Maestro smoke suite on the iOS simulator (docs/E2E.md)
```

**Before saying a task is done:** `npx tsc --noEmit`, `npx expo lint`, `npm test`,
`npm run check:i18n` (the pre-commit hook in `.githooks/` runs exactly these, ~5–10 s).
For UI changes, also run the app (Release build on the simulator) and look at it; run
`npm run e2e -- --build` before a TestFlight build. Building iOS from the command line
**always** needs `-packageAuthorizationProvider netrc` on `xcodebuild` (SwiftPM otherwise
hangs on a Keychain prompt). Android needs
`JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.

## Conventions (follow them; they are load-bearing)

- **Routes vs. logic.** Only screens in `src/app/`. Logic, hooks and feature components
  live in `src/features/<feature>/`. Shared visual primitives in `src/components/ui`.
- **Feature wiring.** A feature that owns a content kind exposes `register.ts`, which calls
  `registerCompletionHandler(kind, …)` (downloads), `onItemRemoved(kind, …)` and
  `registerInit(…)` (startup). Add one import line to `src/features/registry.ts`.
  Inits must be idempotent and fast; heavy work goes in a `setTimeout`/background promise.
- **Contracts between features.** Other features use ZIM archives only through
  `src/features/library/zim.ts` (never `modules/nomad-zim` directly, except the reader's
  `<ZimWebView>`); downloads only through `features/downloads/manager.ts`; installed
  content only through `features/content/items.ts` (one exception: ZIM id migration in
  `library/register.ts` rewrites rows directly). Details in ARCHITECTURE.md.
- **UI.** Use `src/components/ui` and theme tokens; never hard-code colors, sizes or radii.
  Tab roots draw their title with `<Screen title=…>` + `largeTitle()` (native large titles
  render blank inside native tabs on iOS 26). Screens with their own `ScrollView`/`FlatList`
  spread `layout.column` into the content style (720 pt centred column on iPad).
- **i18n.** Every user-facing string goes through i18next, in **both** `es` and `en`
  (`src/i18n/locales/<lang>/<namespace>.json`; new namespaces must be registered in
  `src/i18n/resources.ts`). Catalog texts are `{ es, en }` objects read with `loc()`.
- **Accessibility / tests.** Icon-only controls need `accessibilityLabel`. Never put a
  pressable inside another pressable (iOS merges it — VoiceOver and Maestro can't reach
  it): use `ListRow`'s `trailingAction`. Add a `testID` when an E2E flow needs it and
  list it in `docs/E2E.md`.
- **Database.** Two SQLite files, only opened inside `src/db`: `db()` is `nomad.db` (user data and the
  content registry, small, backed up) and `indexDb()` is `content/index/search.db` (map search index and
  emergency points, derived, out of backups). Key-value state goes through `@/db/kv`, never
  `expo-sqlite/kv-store` (ESLint enforces it, and bans `openDatabaseSync/Async` outside `src/db`).
  Add a migration by appending a SQL string to `MIGRATIONS` (user) or `INDEX_MIGRATIONS` (index) in
  `src/db/schema.ts`; never edit an existing one.
- **Files.** Content lives under `Documents/content/{zim,maps,routing,models,index,partial}` (never the
  cache dir; `index/` holds `search.db`). iOS moves the app container on reinstall/update, so stored absolute URIs go
  stale: read them through `resolveContentUri()` (items, downloads) or resolve by file
  name (`resolveMapFile`). Native libraries want plain paths: `toNativePath()`.
- **expo-file-system 58 gotchas.** int64 values (sizes, progress) arrive as **BigInt**:
  wrap in `Number()`. `File.move/copy` return Promises: await them. Hermes has no
  `Intl.RelativeTimeFormat` (see `lib/format.ts`). **Never `File.digest` a big file** (on iOS it
  holds the whole file in memory: a 2 GB map part got the app killed): use `modules/nomad-files`
  `sha256`, and its `copyInto` for multi-GB copies instead of `FileHandle.readBytes` loops in JS.
- **Pure, tested modules** (`src/lib/{pmtiles,mvt}`, `features/assistant/{rag-core,models,markdown,dictation-core}`,
  `features/library/html`, `features/catalog/opds`, `features/downloads/{mirrors,errors,groups,segments-core,budget-core,restore-core}`,
  `features/maps/{glyphs,geo,extraction-core,places-core,import-core,prepare-core,emergency-core,routing-core,stitch-core,follow-core,country-core,phone,region-terms}`, `features/prepare/{kit,document,passages}`, `features/downloads/manager-core`, `lib/units`, `features/library/{register-core,medical,collection,documents-core}`, `features/content/reconcile-core`, `features/assistant/errors`, `features/credits/credits-core`, `db/{migrate-core,schema}`) use no `@/` aliases and import siblings with `.ts` extensions,
  so `node --test --experimental-strip-types` can load them. Keep it that way and add
  `*.test.ts` next to them.
- **Style of code.** Match the surrounding code: a short header comment per file saying
  what it is and why; comments explain non-obvious decisions (often a platform bug),
  not what the code does. Prettier: `.prettierrc` (single quotes, width 140).
- **Commits.** English, imperative-ish title `Area: what changed` (e.g. `Maps: ship Hebrew
  and Arabic glyphs`), body with the why. Work goes straight to `main` (the early merges of agent worktree
  branches are history; keep it linear from now on). Commit/push only
  when the user asks. Keep `docs/PROGRESS.md` in the same commit as the work it logs.

## Platform pitfalls already paid for

- iOS 26: native large title blank in native tabs → in-content titles (above).
- Android R8 strips libkiwix JNI fields → `modules/nomad-zim/android/consumer-rules.pro`.
- MapLibre Native won't draw a tile while a glyph range fails to load → placeholder
  ranges (`features/maps/glyphs.ts`); bump `VERSION` in `features/maps/assets.ts` when
  `assets/maps/basemap-assets.zip` changes.
- iOS reader needs a persistent `WKWebsiteDataStore` (PouchDB/IndexedDB archives hang on
  the ephemeral one); reader dark mode is a CSS invert with media re-inverted.
- `download.kiwix.org`'s default mirror is often ~300 KB/s: `downloads/mirrors.ts` probes
  the metalink mirrors and picks the fastest.
- Apple Intelligence fails on the iOS 26.5 simulator (`GenerationError -1`); use the
  iOS 27 simulator. llama.rn `stopCompletion()`/`release()` may not return promises.
- A `router.push` before the root navigator is ready is dropped (onboarding waits for it).
- On Android, downloads stop with the process: the manager snapshots resume data on
  background and pumps again on foreground.
- Archive pages must stay offline: the WKURLSchemeHandler / `shouldInterceptRequest` responses
  carry a CSP and iOS compiles a content rule list (`docs/ARCHITECTURE.md`, ZIM library). On Android
  an archive's JS storage (PouchDB…) is per archive origin (`https://<uuid>.zim.local`).
- Valhalla on iOS: never include Valhalla/boost headers in `modules/nomad-route/ios`
  sources. Our copies of their inline templates won at link time and tile-extract
  searches silently failed ("No suitable edges", 171). Call the wrapper's free functions.
  Its `route_action` also turns any C++ exception into 171: attach lldb with a
  breakpoint on `__cxa_throw` to see the real one.
- Routing packs only work with the Valhalla version that built them: keep
  `VALHALLA_IMAGE` (`.github/workflows/country-packages.yml`, `scripts/routing/build-country.sh`)
  and `ENGINE_VALHALLA` (`features/maps/routing-core.ts`, which hides packs of another version)
  in step with valhalla-mobile's bundled Valhalla (3.9.1); the workflow pins it by digest,
  so a bump needs the new tag's digest too.
- kv-store: a zustand `persist` store uses `kvStorage()` (`src/lib/kv.ts`), never
  `createJSONStorage(() => Storage)`. Mixing its async and sync APIs on the first open
  breaks the migration transaction: on a fresh install the settings never hydrated and
  the setup wizard didn't show (~1 in 25 launches; seen in E2E on iOS and Android).

## Working on this repo

- Start by reading `docs/PROGRESS.md` (status + backlog) and the ARCHITECTURE section of
  the area you touch.
- Verify on the iOS simulator (Release build, `docs/DEVELOPMENT.md`) and, for shared or
  native changes, on the Android emulator. UI automation: `axe` / Maestro on iOS,
  `adb shell uiautomator dump` + `input tap` on Android.
- When you finish a block: update `docs/PROGRESS.md` (status, log entry, next steps),
  and ARCHITECTURE.md / E2E.md / STYLE_GUIDE.md if contracts, flows or UI rules changed.
- Releases: follow `docs/RELEASE.md` (tag every store build, e.g. `v1.1.0-12`); the owner
  reviews store listing changes before they're submitted to review. The privacy policy
  (`site/privacy.html`, es + en) must stay exactly true to what the app connects to.
