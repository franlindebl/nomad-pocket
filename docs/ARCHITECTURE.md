# Nomad Pocket — Architecture

Nomad Pocket is a standalone, offline-first mobile port of the ideas in
[Project N.O.M.A.D.](https://github.com/Crosstalk-Solutions/project-nomad): download
knowledge (Wikipedia, medicine, survival, books, courses), offline maps and a local AI
model once, then use everything with no connection. There is no backend: the app talks
only to public content servers (Kiwix, Protomaps, Hugging Face) and only while
downloading.

| NOMAD (server) | Nomad Pocket (device) |
|---|---|
| Kiwix serve + `.zim` | `modules/nomad-zim` — libkiwix/libzim native, `zim://` WebView |
| Kolibri courses | Educational ZIMs + app-side course progress (`features/courses`) |
| Protomaps `pmtiles extract` | `src/lib/pmtiles` — HTTP-range extractor in TS, MapLibre Native |
| Ollama + Qdrant RAG | `modules/nomad-llm` (Apple Foundation Models / Gemini Nano) + `llama.rn` GGUF; RAG over libzim full-text search |
| Curated collections JSON | `src/data/catalog.json` + live Kiwix OPDS |
| Easy Setup wizard | `src/app/onboarding.tsx` + `features/onboarding/packs.ts` |
| Docker apps, benchmark | not applicable |

## Stack

- Expo SDK 58 (React Native 0.88, New Architecture, Hermes, React Compiler, typed
  routes), dev builds with Continuous Native Generation — `ios/` and `android/` are
  generated by `expo prebuild`, gitignored, never edited.
- Expo Router (`src/app`), native tabs (`expo-router/native-tabs`) and native stacks;
  pickers and confirmations are `formSheet`s.
- State: `zustand`. Persistence: `expo-sqlite` (tables) + `expo-sqlite/kv-store`
  (settings, map viewport, preparedness plan).
- Files: `expo-file-system` 58 (`File`, `Directory`, `FileHandle`, `DownloadTask`).
- i18n: `i18next` + `react-i18next`, one namespace per feature.
- Icons: `lucide-react-native`; tab bar uses SF Symbols / Material Symbols.
- Native deps: libkiwix 14.2.1 xcframework (iOS) / `org.kiwix:libkiwix:2.7.0` (Android),
  MapLibre Native via `@maplibre/maplibre-react-native` 11.5, `llama.rn` 0.13.0-rc.8,
  ML Kit `genai-prompt` 1.0.0-beta4 (Android), FoundationModels (iOS 26+, weak-linked).
- Other: `fflate` (gzip/zip), `@protomaps/basemaps` (style layers), `expo-network`
  (Wi-Fi checks), `expo-keep-awake` (map extraction), `expo-document-picker` (ZIM import),
  `expo-location`, `expo-device` (RAM for model choice), `expo-haptics`, `expo-print` +
  `expo-sharing` (plan PDF), `expo-notifications` (local kit reminders only).
- Min OS: iOS 16.4 (Expo 58 floor), Android 8.0 (API 26). License: GPL-3.0-or-later
  (required by libkiwix/libzim).

## Startup

1. `src/app/_layout.tsx` imports `@/i18n` (initialised with the device language), keeps
   the splash screen and calls `bootstrap()`.
2. `features/bootstrap.ts`: imports `features/registry.ts` (each `register.ts` registers
   its completion handler, removal hook and init), opens the database (runs migrations),
   loads installed items into `useContent`, runs every registered init in order, then
   `initDownloads()` (restores the queue) and subscribes the "download finished" toast.
3. Feature inits:
   - library: exclude `Documents/content` from iCloud backup; after 500 ms, register
     loose `.zim` files in `content/zim`, backfill catalog metadata, warm up archives.
   - maps: load markers, delete stale extraction `.part` files, register loose `.pmtiles`.
   - assistant: engine lifecycle (release on background), system-model status watcher,
     chat sessions, forget a selected model whose file is gone.
   - prepare: notification handler (foreground banners) and tap → `/prepare/kit`.
4. The splash hides. Settings hydrate asynchronously from the kv-store; once hydrated,
   if `onboarded` is false the root pushes `/onboarding`, waiting until the navigator
   is ready (an early push is dropped).

## Data model (SQLite `nomad.db`, `src/db/index.ts`)

| Table | Holds |
|---|---|
| `items` | Installed content of every kind (`zim` \| `map` \| `model`): title, language, category, `is_course`, `file_path` (absolute URI), size, version, source URL, `catalog_id`, kind-specific `meta` JSON |
| `downloads` | Persistent download queue: url, dest, bytes, `status` (queued/running/paused/processing/failed/done/cancelled), `pause_state` resume data, `meta` to register on completion |
| `history`, `bookmarks` | Reader state per (item, path) |
| `courses`, `course_progress` | Enrolled courses (syllabus JSON, last lesson) and manually completed lessons |
| `map_markers` | User pins (name, lat/lon, color, note) |
| `map_places` (FTS5) | Offline search index: `names` (indexed, `unicode61 remove_diacritics 2`), name, layer (place/poi/road), kind, lat/lon, `importance` (Protomaps min_zoom; `rank` is reserved by FTS5), `source` (map item id or `pois:<item id>`) |
| `map_localities` | Towns/neighbourhoods of the index (lat-indexed) for "Calle Mayor · Soria" context lines |
| `map_pois` | Emergency points per map item: OSM id (`n…`/`w…`/`r…`, or `t<lat>,<lon>` when taken from the tiles), kind, category, name, operator, phone, opening hours, emergency (ER yes/no) |
| `map_sources` | Per map item: search index version/zoom/date, emergency points fetch date/count |
| `chat_sessions`, `chat_messages` | Assistant conversations, messages with cited `sources` JSON |

WAL mode, two migrations (`v1`; `v2` adds the map search and emergency tables). Add a migration by appending a SQL string to
`MIGRATIONS`; `PRAGMA user_version` tracks what ran. Never edit an old one.

Key-value store (`expo-sqlite/kv-store`): `settings` (zustand persist: `language`,
`contentLanguages`, `theme`, `wifiOnly`, `readerTextScale`, `onboarded`, `aiModelId`),
`maps.viewport` and `prepare` (zustand persist, version 1: the whole emergency plan and
kit, see Preparedness below).

```
  map-assets/v4/           glyphs + sprites unpacked from the bundled zip
```

`app.json` enables `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`, so
users (and the E2E suite) can drop `.zim` / `.pmtiles` files into `content/`: they are
registered at the next launch. iOS changes the container path on reinstall/update:
stored URIs are re-anchored with `resolveContentUri()` (anything under `/content/`).
`hasRoomFor(bytes)` keeps 500 MB of headroom.

## Cross-feature contracts

### Content registry (`src/features/content/items.ts`)
- `upsertItem(input)`, `getItem(id)`, `listItems(kind?)`, `removeItem(id)` (runs the
  kind's removal hook, deletes the file and its history/bookmarks/courses rows),
  `onItemRemoved(kind, hook)`, `useItems(kind?)`, `isInstalled(catalogId)`.
- ZIM items backed by the catalog read title/description from the catalog in the current
  app language (the list refreshes on `languageChanged`).
- Ids: ZIM = catalog id (`wikipedia_es_top_mini`) or the ZIM `Name`/UUID; map =
  `map-<key>`; model = model id (`qwen3.5-2b-q4km`).

### Downloads (`src/features/downloads/manager.ts`)
- `enqueueDownload({ id, kind, title, url, filename, expectedBytes, meta })` — no-op if
  the id is already active; checks free space including what queued downloads still need
  (`NotEnoughStorageError`); persists; at most 2 run at a time.
- Transfers use `DownloadTask` with `sessionType: 'background'` (iOS keeps going in the
  background). Before a fresh Kiwix download, `fastestMirror()` reads the `.meta4`
  metalink and times a 512 KB range request on the first 4 mirrors.
- Android stops transfers with the process: on background the manager pauses running
  tasks and stores their resume data, and pumps the queue again on foreground.
- Relaunch: downloads with stored resume data (paused, or snapshotted on Android
  background) resume; running ones without it go back to the queue and restart from zero
  (iOS: the background session isn't reattached); a download
  that died while `processing` with its file in place is finalised; orphan `.part` files
  are swept.
- Completion: `.part` → `content/{zim,maps,models}/<filename>` → the kind's handler registered with
  `registerCompletionHandler(kind, async (file, record) => …)`, which must `upsertItem`.
  Then `onDownloadFinished` listeners (toast) fire.
- `pauseDownload`, `resumeDownload`, `cancelDownload` (deletes the partial file),
  `dismissDownload`, hooks `useActiveDownloads()`, `useDownload(id)`.
- `startExternalJob({ id, kind, title, totalBytes, cancel })` → `{ update, finish, fail }`
  for non-URL work (map extraction) so it shows in the same downloads UI.

### Catalog (`src/features/catalog`, `src/data/catalog.json`)
- Shape (`types.ts`): `resources` (101: id = Kiwix book name without date, bilingual
  title/description, `language` es/en/mul, pinned `url`, `sizeMB`, `version`, `category`,
  `isCourse`, `subject`, `medical`), `categories` (6: medicine, survival, education, diy,
  agriculture, computing — each with cumulative tiers essential → standard →
  comprehensive via `includesTier`), `wikipedia` (size options per language), 
  `courseSubjects` (math, science, programming, health, general), `courses` (14 ids,
  display order). 23 resources in Spanish, 11 multilingual.
- Accessors: `getResource`, `getCategory`, `tierResources` (cumulative, filtered by the
  user's `contentLanguages`), `courseResources`, `loc()` (bilingual text).
- `downloadResource(r)`: checks connectivity and the Wi-Fi-only setting
  (`OfflineError`, `WifiRequiredError`), resolves the newest version via Kiwix OPDS
  (`opds.ts`, `https://opds.library.kiwix.org/catalog/v2/entries`, 5 s timeout, falls back
  to the pinned URL) and enqueues it with registration meta.
- `DownloadButton` / `startResourceDownload` / `showDownloadError` (offers "use mobile
  data" on `WifiRequiredError`). The Explore screen searches the whole Kiwix OPDS catalog.
- `scripts/validate-catalog.mjs` checks the schema and that every URL resolves with the
  expected size. Edit the JSON by hand; keep ES and EN texts.

### Starter packs (`features/onboarding/packs.ts`)
`light` (Wikipedia top-mini + medicine & survival essential tiers, primary language
only, items ≤ 300 MB), `balanced` (top-nopic + every essential tier, ≤ 1.5 GB each),
`complete` (all-mini + every standard tier), `none`. The wizard (language → pack sized
against free space → tips) enqueues the pack's resources.

### ZIM library (`modules/nomad-zim`, facade `src/features/library/zim.ts`)
- Facade (the only entry point for other features): `openArchive(itemId, fileUri) →
  ZimInfo`, `closeArchive`, `ensureArchive`, `suggest` (title index, search-as-you-type),
  `search` (full-text with snippets, interleaved across archives), `getArticleText`,
  `getArticleHtml` (follows `<meta http-equiv="refresh">` redirect pages),
  `getLinks`, `getHeadings`, `listArticles`, `getJson`, `getMainPath`, `randomPath`,
  `getOpenInfo`, `excludeFromBackup`. Functions taking item ids open installed archives
  lazily; a per-item generation counter makes opens that finish after a close fail with
  `ARCHIVE_CLOSED` instead of leaking an open archive.
- Native: iOS wraps the prebuilt `CoreKiwix.xcframework` (fetched by
  `modules/nomad-zim/scripts/fetch-ios-libs.sh` from `postinstall`, gitignored, pinned
  14.2.1-2 + md5) with an Objective-C++ class (`NZArchive`) and a Swift `ZimRegistry`;
  Android uses Maven `org.kiwix:libkiwix` with a Kotlin `ZimRegistry` (closed archives
  are disposed after 120 s so in-flight reads finish; R8 keep rules in
  `consumer-rules.pro`). All libzim work runs off the main thread.
- `<ZimWebView archiveId path darkMode textZoom onNavigationChange onLoadEnd />` serves
  `zim://<uuid>/<path>` (iOS, `WKURLSchemeHandler`, persistent website data store) or
  `https://zim.local/<uuid>/<path>` (Android, `shouldInterceptRequest`, wide viewport),
  with HTTP Range (206) for media, redirects resolved, external links opened in the
  system browser. Ref: `goBack`, `goForward`, `reload`, `loadPath`, `findInPage`,
  `clearFind`, `setTextZoom`, `setDarkMode`. Dark mode = CSS invert with media
  re-inverted; the page always sees `prefers-color-scheme: light`; pages dark by design
  get `data-nomad-native-dark` and are left alone.
- Registration (`library/register.ts`): `registerZimFile(fileUri, meta?)` probes the header
  under a temporary id, matches the catalog (download meta → file name without the
  `_YYYY-MM` suffix → ZIM `Name`), migrates history/bookmarks/courses of a stale id for
  the same file, opens under the final id, upserts the item and deletes the previous file
  when an update replaced it. Used by downloads, Files import (`library/index.tsx`, copies
  through `partial/`) and the startup scan.
- Pure helpers: `html.ts` (HTML → text, link/heading extraction, ZIM href resolution,
  meta-refresh targets; unit tested), `titles.ts` (`pageTitle` ignores file-name titles),
  `history.ts` (visits, bookmarks), `useZimSearch`.
- Reader (`app/reader/[itemId].tsx` + `library/components`): toolbar (back/forward page
  history, in-book search sheet, bookmark, text size popover, more), table of contents
  (h2/h3), find in page (iOS JS highlighter with counts, Android native find),
  library/history sheet, medical disclaimer for `medical` items, dark mode, spinner until
  the first page loads.

### Courses (`src/features/courses/courses.ts`)
- A course is an installed ZIM with `isCourse`. `ensureCourse(itemId)` enrols (idempotent)
  and builds the syllabus once: main-page links in document order → freeCodeCamp
  `content/curriculum/index.json` → HTML articles in title order (`listArticles`); max 400
  lessons, media links dropped. A failed build stores NULL (retried later); an empty
  syllabus is retried once per launch.
- A lesson is done when it is in `course_progress` (manual check) or in `history`
  (opened). `recordCourseOpen`, `setLessonDone`, `resetCourse`, `courseProgress`,
  `nextLesson`, `useCourses` (version counter for re-renders).

### Maps (`src/lib/pmtiles`, `src/features/maps`, `src/app/(tabs)/maps`)

**Extractor** (`src/lib/pmtiles`, pure TS, no `@/` aliases so `node --test` loads it):
`readArchiveInfo`, `planExtract(source, { bbox, minZoom, maxZoom, overfetch, signal,
onProgress })` → `ExtractPlan` (exact archive size + download size; this *is* the
dry-run estimate), `executeExtract(source, plan, sink)`, `extract()` = both.
I/O is injected: `RangeSource` (`FetchSource` = HTTP Range with retries and ETag
pinning via `If-Match`; `BytesSource` for tests) and `Sink.write(offset, bytes)`
(app: expo-file-system `FileHandle`; tests: memory / `node:fs`).

How it works (same idea as `pmtiles extract`): bbox → Hilbert tile-id ranges per
zoom via quadtree descent (descendants of a tile form one contiguous id range, so
ranges are O(perimeter)); walk the root directory and fetch only the leaf
directories whose id span intersects the ranges (coalesced); collect entries,
deduplicate contents by source offset (keeps the output clustered), lay out
`header | root | metadata | leaves | tile data`, rebuild directories (root ≤ 16 KiB,
gzip via fflate) and coalesce tile byte ranges (merge smallest gaps while overfetch
≤ 5 %, requests ≤ 4 MiB). Tiles are written straight to their final offsets, so
downloads run 4 at a time out of order. Measured against build 20261023: world
z0–5 15 MB (2 s plan), central Madrid z0–15 10.7 MB, Comunidad de Madrid z0–14
58 MB, Spain z0–14 1.6 GB (plan 4 s, 2.9 MB of directories). Areas above 2.5 M tiles
are refused (choose less detail).

**Extraction jobs** (`extraction.ts`): `latestBuild()` reads
`build-metadata.protomaps.dev/builds.json` (cached 6 h) → `build.protomaps.com/<YYYYMMDD>.pmtiles`;
`estimateExtract` caches plans; `startMapDownload({ key, title, bbox, minZoom, maxZoom,
regionId, estimate })` runs as an external download job on the JS thread with the screen
kept awake, writes `partial/map-<key>.pmtiles.part`, moves it to `content/maps/<key>.pmtiles`
and upserts `{ kind: 'map', id: 'map-<key>', meta: { role: 'world'|'region', bbox,
minZoom, maxZoom, buildDate, regionId } }`. Zoom choices: 12 / 14 / 15; the world
basemap is z0–5. Jobs live in memory (not resumed after a kill). Loose `.pmtiles` files
are registered at startup from their header (`register.ts`; a region id as file name
gives the region's name).

**Rendering**: MapLibre Native (iOS 6.31 / Android 13.6 via maplibre-react-native
11.5) reads local archives natively with `pmtiles://file:///…/x.pmtiles` — no
local tile server or protocol handler needed; the app opens no network sockets while
rendering. Style (`style.ts`) = `@protomaps/basemaps` `layers()` per source (light/dark
from the app theme, labels in the app language); the world basemap is the bottom source
and each region gets its own layer stack on top (sorted by max zoom), so the map is never
empty outside a region (duplicate labels collapse through symbol collision).
`useMapSources.resolveMapFile` resolves files by name (container moves).

**Glyphs and sprites** (`assets.ts`, `glyphs.ts`): Noto Sans Regular/Medium/Italic
ranges for Latin, Latin Ext, Greek, Cyrillic, Hebrew, Arabic and their presentation
forms, Thai, Georgian, Ethiopic, punctuation, plus Protomaps' pre-shaped Noto Sans
Devanagari, and v4 sprites ship as `assets/maps/basemap-assets.zip` (3 MB), unpacked once
to `Documents/map-assets/v4/` (bump `VERSION` when the zip changes). Every other range
gets an empty placeholder PBF: MapLibre Native doesn't draw a tile while a glyph range it
needs fails to load. CJK is drawn with the system font. Bengali, Tamil, other Indic
scripts, Myanmar and Khmer stay placeholders (MapLibre Native can't shape them). The
style references the files with `file://` URLs. Regenerate with `scripts/maps/`
(`dl-assets.mjs` + `make-zip.py`; `dl-ne.mjs` + `make-regions.mjs` for regions).

**Search index** (`places.ts`, pure parts in `places-core.ts`, `src/lib/mvt/decode.ts`,
`src/lib/pmtiles/reader.ts`): every installed map is decoded once into `map_places`
(FTS5) — `places` (towns, neighbourhoods, countries), named `pois` (except street
furniture) and named `roads` (one row per name and tile; deduped within 1.5 km at query
time). Reads one zoom: the archive's max zoom capped at 15, lowered until ≤ 40 000 tiles
(`pickIndexZoom`; Spain at z14 is indexed at z12, so minor streets are missing there);
the world basemap at z5. A queue indexes one map at a time, 24 tiles per batch with a
`setTimeout(0)` between batches (JS thread stays responsive; ~1–6 ms per dense tile in
V8, more in Hermes). Triggers: 4 s after startup for maps whose `map_sources.index_version`
≠ `INDEX_VERSION` (bump it when `tileRows` changes), and `onMapInstalled` after a download
(re-index). Removing a map cancels its job and deletes its rows. `searchPlaces(text, near)`
= FTS prefix match (`"word"*` per word) → `rankHits` (exact > prefix > word match, place >
POI > street, importance, log-distance from the map centre) → nearest locality as context.
The search sheet also matches saved places and parses coordinates (`geo.ts`: decimal,
DMS with N/S/E/W/O, UTM with band letter). No house numbers: Protomaps tiles carry none.

**Emergency points** (`emergency.ts`, pure parts in `emergency-core.ts`): 17 kinds in 5
categories (health, security, water & shelter, supplies, institutions) from OSM tags.
After a region download (and from the Emergencias sheet) the app POSTs an Overpass query
for the region's bbox, split into ≤ 3° cells (a 3° cell over central Spain: ~60 s, 25k
points; Comunidad de Madrid: 15k points, 1.2 MB TSV), to three public servers in turn,
with a per-request timeout (query timeout + 30 s; servers that are at capacity hold the
connection). TSV output (`[out:csv]`) keeps it small. Rows replace the region's
`map_pois` and go into the search index under `pois:<item id>`. Offline fallback: while
indexing, emergency-kind POIs found in the tiles (named or not, e.g. drinking water) are
stored as `t…` rows unless the region already has Overpass points — at z15 that is most
of them, at z12/14 only the important ones (Protomaps gives most POIs min_zoom 15–17).
Queries: `nearestEmergencyPlaces(category, from)` (equirectangular ORDER BY, GROUP BY
osm_id across overlapping regions), `emergencyPlacesIn(bbox)` for the map layer (zoom ≥ 11).
`emergencyNumber()`: 911 for the device region in most of the Americas, else 112.

**Routing** (`modules/nomad-route`, `routing.ts`, `routing-packs.ts`, pure parts in
`routing-core.ts`, `valhalla-defaults.json`): Valhalla 3.9.1 on the device through
Rallista valhalla-mobile 0.6.4 (MIT). iOS: the static xcframework + `tzdata.tar` are
fetched by `modules/nomad-route/scripts/fetch-ios-libs.sh` (postinstall, sha256-pinned);
`NRRouter.mm` calls only the wrapper's plain functions (`create_valhalla_actor`, `route`,
`matrix`) and **includes no Valhalla header** — inline templates instantiated in our file
won over the library's at link time and every tar search came back empty (171) while
loose tiles worked. Swift untars `tzdata` into `Library/tzdata` on first open. Android:
Maven `io.github.rallista:valhalla-mobile:0.6.4` (`Valhalla(configPath).routeRaw`).
Isochrones are not exposed by either wrapper (later). The module takes a config JSON
(`valhallaConfig(defaults, tar)`; native writes it to a file per pack) and request JSON;
errors come back as `valhalla <code>: <message>` (`routingErrorKind`: 171 no road near,
442/170 no path, 154 too far). A **routing pack** is a Valhalla tile extract
(`content/routing/<id>.tar`, mmapped, never unpacked), item kind `route`; its coverage
(`meta.bbox` + `meta.cells`, the 1° cells holding its local-road tiles — a bbox
over-claims: Spain's covers Portugal) comes from the manifest or, for loose files, from the
tile names in the tar (`tileCoverage`). `computeRoute(from, to, costing)` tries the packs
covering both ends, smallest first, moving on after "no road" / "no path" (packs are
whole countries; packs installed from the first catalogs may be Spanish regions, tile
subsets of the country build, which lack the roads a trip needs past their edge). Engine calls are
serialized in JS (open + route never interleave with another request or a close). **Catalog**: `routing-manifest.json` in the
fixed release `routing-index` (override: `EXPO_PUBLIC_ROUTING_MANIFEST_URL`, set by
`scripts/e2e.sh` for its local pack server), cached in kv-store; each pack lists its tar
parts (≤ 1900 MiB, GitHub's asset limit is 2 GiB), a `.pois.tsv` and a `.streets.tsv`
(street and locality names: kind, name, lat, lon). `downloadPack` checks the room needed
up front and queues the parts, POIs and street names not on disk yet (a retry
only fetches what is missing) through the download manager (kind `route`). The
completion handler fails a file whose size differs from the manifest; when every part is
there it appends them into `<id>.tar.tmp`, checks the size, renames it, registers the
item, then deletes the parts and imports the POIs into `map_pois` / the search index
under `route-<id>` (`storeEmergencyPoints`, batched, shared with the Overpass sync), then
the street names into `map_places` / `map_localities` (`indexPackStreets`, batches of
5000 with a yield; source `route-<id>`, and a `map_sources` row with `index_version` so
search works with no map installed). The map index reads one zoom level under a tile
budget, which for a big map holds only the main roads: the pack's names fill that in.
Packs installed before the catalog had street names fetch just that file
(`fetchMissingStreets`, after each catalog refresh; the catalog refreshes 4 s after
startup when a pack is installed). Search also runs the match restricted to 30 km
around the user, so a common street name nearby isn't lost among thousands. A
kill mid-assembly is recovered by the manager re-finalizing the last part (all parts are
still on disk); 4 s after startup `sweepRoutingFiles` deletes temp files and parts/POI/
street files no active download belongs to. sha256 is in the manifest but not verified yet. Removing a pack closes the router
and drops its POIs. **Packs are built** by `.github/workflows/routing-packs.yml` (monthly
+ manual): `scripts/routing/build-country.sh` per country of `packs.json` inside
`ghcr.io/valhalla/valhalla:3.9.1` — Geofabrik PBF(s) (md5-checked; several are
`osmium merge`d: Spain + Canary Islands) + admin boundaries (levels 2/4) from Overpass →
`valhalla_build_admins` → `valhalla_build_tiles` (retried: 3.9.1 segfaults now and then)
→ one tar per country (the owner wants whole-country packs only) → emergency points
(`osmium tags-filter` + `emergency-points.py`, same columns as the Overpass TSV) → street
names (`streets.py`, one row per name per ~1 km) → split → `manifest.py` (bbox, cells,
parts with sha256; empty side files dropped).
Each run gets its own tag (`routing-YYYYMMDD-<run>`) and each pack records its release,
so countries not rebuilt in a run keep their previous files (a rebuilt country replaces
all its packs; countries no longer in `packs.json` are dropped); `routing-index` is updated
last, and the run fails rather than drop countries if the previous manifest can't be
read. Before publishing, every pack's cells are clipped to its Geofabrik extract's
`.poly` (`manifest.py clip`: extracts keep whole ways that leave them, ferry lines above
all, which would make Ireland's pack "cover" Bilbao). Then releases that neither the new
nor the previous manifest points at are deleted.

**Guidance** (`guidance.ts`, `GuidancePanel.tsx`): a zustand store watches GPS
(`BestForNavigation`, 3 m) and the compass while a target is set and keeps the screen
awake. With a pack covering both ends it asks for a route (car / foot / bike chips) and
follows it: `routeProgress` snaps each fix onto the shape (searching forward from the
last segment), giving the next maneuver, distance to it and what is left (time scaled
from Valhalla's estimate); two fixes off the route (> max(40 m, accuracy ≤ 80 m)) trigger
a reroute, at most every 10 s. The map draws the route line and frames it on the first
route of each target and on a mode change. `maps/route-steps` lists the maneuvers. A
failed reroute keeps the old route; with no route, the store retries every 10 s (back on
a road, a fresh fix after a stale one — last-known fixes older than 2 min are ignored).
The start heading is the GPS course when moving (> 2 m/s), else the compass on foot or
bike. Without a pack, or when Valhalla finds no way, it falls back to the straight line: an arrow rotated by
bearing − heading (map bearing without a compass), distance + 8-point direction, time
at a nominal speed, and a "Descargar rutas" button (`maps/routing-packs`); installing a
pack mid-guidance retries the route (`retryRoute`). Arrival ≤ max(20 m, accuracy ≤ 50 m) from the target, with a haptic; at the route's end
(it stops at the road nearest the target) the last stretch switches to the arrow. A session counter drops superseded starts, a
request counter late routes. Turn-by-turn voice, background location and rerouting
polish are phase 3 (`docs/MAPS_NAVIGATION_PLAN.md`).

**Map screen extras**: search pill (opens `maps/search`), red Emergencias FAB
(`maps/emergency`, also from a Home card via `unstable_settings.initialRouteName`), GeoJSON
layers for emergency points (category colours, labels from z15, tap → place card), the
selected place (ring), the route line and the straight guidance line; bottom `PlaceCard` (kind, operator/police
force, ER badge, hours, distance, decimal + UTM, Llévame / Guardar / Llamar) or
`GuidancePanel`.

**Regions** (`regions.json`, 312): Natural Earth countries with far-flung overseas
territories trimmed from the bbox, 19 Spanish autonomous communities, 51 US states;
ES/EN names, continent. **UI state** (`store.ts`): persisted viewport + one-shot camera
requests from sheets. **Markers** (`markers.ts`): `map_markers` + zustand store.
Routes: `maps/index` (map, locate-me, compass, long-press to add a pin), sheets
`regions` (installed + world + visible area + pick), `pick` (search regions), `download`
(zoom choice and exact size before confirming), `markers`, `marker` (edit/delete),
`search`, `emergency`, `routing-packs` (catalog: installed, for this area, all) and
`route-steps`.

### Assistant (`modules/nomad-llm`, `src/features/assistant`, `src/app/(tabs)/assistant`)
- `modules/nomad-llm`: `getSystemModelStatus()` → `{ status: available | notEnabled |
  deviceNotEligible | modelNotReady | downloadable | unsupportedOS | unsupported,
  provider: 'apple' | 'gemini' | null }`, `generate(requestId, { prompt, system?,
  temperature?, maxTokens? }, onDelta)` (events `onDelta {requestId, delta, reset?}` /
  `onDone` / `onError`), `cancel(id)`, `downloadSystemModel()` (Android), `route(prompt,
  instructions)` → `{ search, query }` (iOS: guided generation with a `@Generable`
  struct, greedy). iOS weak-links FoundationModels (iOS 26+); Android uses ML Kit GenAI
  Prompt (Gemini Nano on AICore).
- `models.ts`: curated GGUF list, URLs pinned to a Hugging Face commit with exact sizes:

  | id | Size | Min RAM | Context |
  |---|---|---|---|
  | `qwen3.5-0.8b-q4km` | 533 MB | 3 GB | 4096 |
  | `qwen3.5-2b-q4km` | 1.28 GB | 4 GB | 4096 |
  | `qwen3.5-4b-q4km` | 2.74 GB | 7 GB | 6144 |
  | `gemma-4-e2b-q4km` | 3.11 GB | 8 GB | 6144 |

  `modelFit(model, ramGB)` and `recommendModel(ram)` (largest Qwen that fits). Items are
  `kind: 'model'`, id = model id; `useSettings.aiModelId` is a model id or `'system'`.
  The first downloaded model becomes the active one. `tools`: how the model calls
  search_library (`thinking` for Qwen3.5, which only calls tools with reasoning on;
  `direct` for Gemma 4). Catalog GGUF files copied into `content/models` by hand (exact
  name and size) are registered at startup, which is also how E2E seeds a model.
- `engine.ts`: one `Engine` interface over `SystemEngine` (~4k-token window) and
  `LlamaEngine` (llama.rn, chat template from the GGUF via `jinja`, thinking disabled,
  GPU layers on real iOS devices, CPU elsewhere). `engine.decides` says how the model
  chooses to search: `tools` (GGUF: pass 1 offers search_library — Qwen with thinking
  on, budget 256 tokens — and either answers or calls it; pass 2 answers from the tool
  result with `tool_choice: 'none'`), `router` (Apple FM: `route()`), or null (Gemini
  Nano: heuristics). `withEngine(modelId, fn)`,
  `stopGeneration()`, `releaseEngine()`, `releaseIfModel()`. One engine alive at a time;
  released on background and after 4 idle minutes.
- Chat or search (`chats.ts` `answer()`, rules in `rag-core.ts`): library off or empty →
  plain chat. Otherwise `guessIntent` (small talk, thanks, "who are you", and requests
  about the previous answer such as "resúmelo" → chat) runs first on every engine; then
  the model decides when it can (`tools` / `router`, which also writes the query), and
  an engine that can't searches every question. The "Buscar en mi biblioteca" button
  forces a search (`searchLibraryFor`). The prompts were tuned on llama.cpp and Apple FM
  with a chat/search bench; the numbers are in the comments next to them.
- RAG (`rag-core.ts` pure + tested, `rag.ts`): question (or the model's query) → language
  detection and keyword queries (stopwords, light stemming, es/en; a follow-up such as
  "¿y cómo se trata?" gets the previous question's keywords, `followUpTopic`) → libzim
  full-text search across archives (reciprocal-rank fusion) → up to 6 distinct articles
  (redirects counted once) → chunks of 650 chars → BM25 (with title and search-rank
  boosts) → drop chunks sharing too few question terms (`relevantChunks`) → pack the
  best chunks into the model's budget as numbered sources → `[n]` citations, in the user
  turn (`sources` prompt) or as the tool result. Health questions get an extra caution
  rule.
- `chats.ts`: sessions/messages in SQLite, `useChat` store, `sendMessage` (token budget:
  answer 768 tokens for GGUF / 600 for system, ~25 % of the rest for history, the rest for
  sources; phases loading → thinking (router / tool decision) → searching → generating;
  throttled streaming), `stopAnswer`
  (also during search/load), only cited sources are kept on the message (all if none
  cited), answers to a deleted conversation are dropped. `searched` (in memory only) marks
  answers given without the library: the latest one shows "Buscar en mi biblioteca".
- UI: chat with streaming Markdown (`markdown.ts` parser, `ui/Markdown.tsx`), source chips
  → reader, stop, "use my library" toggle, starters, AI/health disclaimer; conversations
  sheet; models screen (system model status, downloads, fit badges).

### Preparedness (`src/features/prepare`, `src/app/(tabs)/(home)/prepare`)

Emergency plan and kit, inspired by "if the internet goes down" checklists: things a
downloaded library can't hold because they are the user's own. Entry: a card on Home
(`PrepareHomeCard`: kit progress, contacts, items expiring) → `/prepare`.

- Data (`types.ts`, `store.ts`): one JSON document in the kv-store key `prepare` —
  contacts, important numbers, people (medication, allergies, blood type), two meeting
  points (`primary`, `secondary`), home notes, household (adults ≥ 1, children, pets,
  days 3/7/14), kit entries by item id (`have`, `expires` "YYYY-MM", `note`,
  `reminderId`) and custom items (`custom-<uid>`). Nothing leaves the device except the
  PDF the user shares. No SQL tables (no migration to coordinate).
- Meeting points can link a map pin (`useMarkers` read-only); its lat/lon are copied so
  the plan keeps the place if the pin is deleted. "Show on map" uses `useMapUi.focus`.
- Kit (`kit.ts`, pure, tested): 29 template items in 8 categories (ids are stable keys —
  never rename), children/pet items only when the household has them. Quantities: water
  4 L/person/day + 1 L/pet/day, food 2000 kcal/adult and 1400/child per day, medication
  max(days, 30). Expiry: `soon` = this or next month, `expired` = earlier.
  `rows.ts` turns template + entries into translated groups and a summary.
- Reminders (`reminders.ts`): local notification at 10:00 on the 1st of the month before
  expiry (none if that moment has passed); permission asked the first time an expiry is
  saved; Android channel `reminders`. The expo-notifications plugin has
  `enableRemoteNotifications: false`, so there is no push entitlement.
- PDF (`document.ts` pure + `share.ts`): A4 HTML (blank rows to fill by hand when a
  section is empty, then the kit checklist) → `Print.printToFileAsync` → renamed
  to "Plan de emergencia.pdf" in the cache → `Sharing.shareAsync` (print, Files, AirDrop).
- The hub also lists offline guides from the catalog (Ready.gov es/en, post-disaster,
  medicine, water, food preparation) filtered by content languages, with download buttons.
